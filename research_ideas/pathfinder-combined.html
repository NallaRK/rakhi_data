PATHFINDER02 / 16 · The Problem
Why we need this

Five compounding pain points

35 repositories. 100+ developers. Stories written in business language. Each one a routing puzzle that costs hours before any code is written.

01

Vague stories

POs write business stories without technical context. Developers reverse-engineer the implementation surface area during grooming.

02

Repo routing overhead

With 35 repos and no systematic method, developers spend hours deciding which repos require changes for a given story.

03

Ad-hoc Copilot prompting

Each developer crafts their own prompts from memory. Quality varies by individual. No standardized workflow exists.

04

Cross-repo blind spots

Shared component and API changes affect many MFEs. Impact analysis is manual, error-prone, and often discovered in QA.

05

Inconsistent code generation

Without codified conventions, Copilot generates code that misses team standards, requiring rework during review.

PATHFINDER03 / 16 · The Vision
What Pathfinder enables

One ticket. One workflow. The whole codebase, understood.

A standardized, AI-guided pipeline that takes a JIRA ticket and produces a reviewed implementation across our 35-repo polyrepo. Designed for developers and product owners alike.

For Product Owners

Write stories in business language. Pathfinder enhances them with affected repos, APIs, and database impacts — directly in JIRA.

For Developers

Type the ticket ID. Review a guided analysis, plan, and implementation across repos. No more ad-hoc prompting from memory.

PATHFINDER11 / 16 · Technology Choices
Open source · No Docker · No Yarn

Why these tools, and not others.

ArcadeDB
Apache 2.0

Multi-model graph + document + vector database. JVM-native, runs as a single java -jar. Handles concurrent writes (unlike KuzuDB, which was archived in 2025). Built-in MCP server.

SCIP Indexers
Apache 2.0

scip-typescript and scip-java provide compiler-grade symbol resolution that Tree-sitter cannot — including TypeScript type inference and Spring DI binding.

VSCode Copilot Enterprise
Existing License

Native support for custom agents, instructions files, and MCP servers. Already paid for. Eliminates the need for a separate AI coding tool.

DeepWiki MCP
Devin · Phase 1 Only

Useful as a starting context layer for Phase 1 validation. Replaced in Phase 2 because per-query ACU consumption ($2/ACU) makes ongoing usage at 100+ developer scale cost-unpredictable.

GitHub Actions (existing)
Existing CI/CD

Already in use across all 35 repos. Phase 3's SCIP indexing piggy-backs on the existing merge-trigger workflow — no new CI infrastructure to provision.

AGENTS.md Standard
Linux Foundation

Cross-tool context standard, donated to the Agentic AI Foundation in 2025. Adopted by 60,000+ projects. Future-proofs us against tool changes (Copilot, Claude, Devin all read it).

PATHFINDER13 / 16 · Honest Tradeoffs
What we gain · What we accept

No silver bullets. Real tradeoffs, named.

What Pathfinder Gives Us

+
Standardized workflow — every developer follows the same pipeline, eliminating per-individual quality variance
+
Faster routing decisions — affected repos identified by the agent with file-path citations, not guesswork
+
Cross-repo blast radius visible early — impact discovered before coding, not in QA
+
Pattern compliance built-in — copilot-instructions.md forces every generation through team standards
+
Reversible at every phase — Phase 1 has zero infrastructure. We can stop after week 2 and lose nothing material.
+
PO benefits too — JIRA automation enhances stories with technical context without POs leaving their tool

What We Accept In Return

−
AI hallucination is a real risk — agents must cite file paths; planner verifies; human reviews at every step. Mitigated, not eliminated.
−
Documentation maintenance burden — pathfinder-hub needs a named owner, not "the team." Wiki rot kills projects like this.
−
Learning curve for agent authoring — writing good .agent.md files takes iteration. The first version will produce mediocre output.
−
Phase 3 carries operational weight — ArcadeDB needs JVM tuning, backups, monitoring. 2–4 hours/week of platform-engineering attention.
−
SCIP adds CI time — 30–60 seconds per build. Acceptable, but it's a real cost to every PR.
−
Adoption isn't automatic — developers must actually use the agents. If the workflow feels slower than habit, it dies.

PATHFINDERRisk Assessment
Top six risks · ranked

What can go wrong. What we do about it.

High 1

Developers don't adopt the agent workflow

Entire initiative fails if developers find it slower than habit.

→ Phase 01 MVP with 5–8 developers validates before scaling. Stop/iterate if adoption fails.
High 2

AI hallucination in story analysis

Agent claims components or files exist that don't.

→ Agents MUST cite file paths from manifest. Planner verifies via @workspace. Human review at every step.
High 3

Wiki documentation goes stale

The #1 killer of internal documentation projects. Wiki rot kills trust.

→ Quarterly automated refresh GHA. Manifest sync on every hub update. Named owner accountable for uptime.
Medium 4

JIRA ticket content exposure to AI context

JIRA MCP exposes ticket data (possibly PII, compliance) to Copilot context.

→ JIRA MCP scoped read-only. Server in org network. InfoSec review before Phase 02 deployment.
Medium 5

MCP server downtime mid-sprint

Pathfinder-hub MCP becomes a critical-path dependency.

→ Agent fallback to per-repo manifest + @workspace. Degraded cross-repo awareness, not full outage.
Medium 6

Phase 03 operational burden grows

ArcadeDB needs DBA-level attention to stay healthy.

→ Named platform owner. 2–4 hr/week budgeted. Nightly backups. Skip Phase 03 entirely if Phase 02 is sufficient.
